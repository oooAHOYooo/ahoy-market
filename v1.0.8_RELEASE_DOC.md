## 2. Storage Fix: GCS / S3 Delivery
**Current State:** Some audio files hosted on Google Cloud Storage (GCS) are failing to play, while Amazon S3 files work correctly.
**Status:** Partially fixed and logged on 2026-04-26.
**Action/results:**
- Investigated the `proxy_audio` route in `app.py` (around line 1975). The whitelist already allows `https://storage.googleapis.com/...`, S3 URLs, and `ahoycollection` URLs.
- Verified public GCS sample headers with `curl`: sampled objects return `200` / `206`, `audio/mpeg`, byte ranges, and content length.
- Found that the sampled GCS responses do not return `Access-Control-Allow-Origin` for `https://app.ahoy.ooo`, `capacitor://localhost`, or `http://localhost`.
- Found the Vue player was forcing `crossOrigin = 'anonymous'` in `spa/src/stores/player.js`; removed it to match the legacy player behavior that already avoids CORS mode.
- Logged in to Google CLI as `alex@ahoy.ooo`, confirmed both buckets had CORS for `https://ahoy.ooo` but not `https://app.ahoy.ooo` or `capacitor://localhost`, then updated both bucket CORS policies from `docs/deployment/gcs-audio-cors.json`.
- Verified post-fix headers: `https://app.ahoy.ooo` and `capacitor://localhost` now receive `Access-Control-Allow-Origin`; range requests return `206` with exposed range headers.
- Android test output: build a v1.0.7.5 AAB (`versionCode 1772056493`) from this fix set for Play Console/internal testing before final v1.0.8 packaging.
- Detailed log: `docs/RELEASE_NOTES_v1.0.8.md` and `docs/troubleshooting/GCS_AUDIO_DELIVERY.md`.
